# 归档与卡片查询

**created** 2026-11-17 · **last-change** 2026-11-17 · **status** draft

## 现行行为
<!-- @topic: ArchiveCardQuery -->

发版时把终态卡移入 `docs/archive/<version>/{change,task}/`，在批次总账中冻结卡片路径和主题归属。现行总账保留活跃卡和设计正文入口。普通校验与 `--topic <主题>` 共用全量采集，所以即使只命中一张活跃卡，查询也会读取已登记的归档卡正文，并遍历物理归档区。[索引总账与路由规约](../../../references/04-index-routing.md) · [校验器](../../../scripts/adflow_verify.py)

初测使用 20 个批次和 1 张匹配卡，历史卡均不属于查询主题。0、500、2,000、5,000 张归档卡时，现行查询的中位耗时分别为 57、132、321、695 毫秒。每组预热后独立运行 CLI 7 次，计时包含进程启动。数据来自本机合成项目。

## 拟交付行为

| 意图 | 入口 | 读取范围 |
| --- | --- | --- |
| 按主题查当前卡片 | `scripts/adflow-verify --topic Core --scope active` | 两份现行总账的主题及卡片登记 |
| 按主题追溯已归档卡片 | `scripts/adflow-verify --topic Core --scope history` | 批次总账，以及现行总账里兼容旧布局的归档登记 |
| 查询旧版的完整主题结果 | `scripts/adflow-verify --topic Core` | 沿用全量复核、现有输出和退出语义 |
| 发布及完整性审计 | 普通校验、`--release <version>` | 现行与归档总账、卡片实体和现有完整性门禁 |

- `active` 按现行卡池路径分流，查询过程中不发现、遍历或读取归档目录。已经收口但尚未归档的卡仍在现行卡池。历史登记即使留在旧总账里，也不会出现在活跃结果中。
- `history` 用声明 `adflow-archive-batch-v1` 的批次总账定位历史卡。它兼容旧总账的历史登记及任务总账的 `cards` 旧键。迁移过渡期的同号同路径合并一次，同号异路径显式报告冲突。结果包含卡号、状态、标题、原始版本、归档批次和路径。
- 两种查询均接受 `--json`。索引中缺失的可选字段留空。路径必须是所属轨道内的项目相对路径，拒绝绝对路径和越界路径。合法总账没有命中时返回空列表。所需总账缺失、损坏或匹配登记失效时给出可定位的诊断，避免把部分结果当作完整结果。卡片实体及其证据只在读者按结果路径查看时读取，实体完整性由普通校验负责。
- 正式知识查询优先查 `docs/official/`（如已建立）、现行设计和使用文档。查历史原因或验收证据时进入归档路径。若另有知识库构建器，配置搜索范围时需确保已引用的历史依据仍可达。

## 任务与验证

| 卡片 | 前置 | 验收重点 |
| --- | --- | --- |
| T01 活跃卡查询 | 无 | 读取范围与归档规模无关，旧 `--topic` 继续按原合同工作 |
| T02 归档卡查询 | T01 | 新旧路由兼容，多主题命中，历史列表不读归档卡正文 |
| T03 回归与使用说明 | T01、T02 | 保持归档门禁，记录同条件对比，更新查询入口指引 |

三张卡均纳入 `v1.8.0`。M1 依次交付 T01 和 T02。M2 由 T03 完成性能复测、兼容校验和使用指引，三张卡均收口后才能完成本批次发布。以归档文件读取数作为性能验收的主要指标，同时记录中位数和 P95。若大量批次下总账解析仍是瓶颈，再根据实测评估可重建索引。
