# 01 - 核心心智模型 (Mental Model)

`ad-flow` 构建在三大核心支柱心智之上，理解这些心智是 AI Agent 与人类顺畅协作的前提。

---

## 一、模块化现行基线模型 (Living Baseline)

- **概念**：`docs/devel/design/` 下的设计文档是系统的**唯一现行真理（Living Baseline）**。它只描述“系统现在此刻是如何工作的”，不承担冗余的历史日记职责；
- **架构组织**：采用 **“1 篇宏观总体设计 (`00-系统总体设计.md`) + N 篇独立功能微文档 (`01~99`)”** 的解耦架构；
- **自洽性**：任何代码规则的变更，最终必须同步反哺到对应功能文档正文中，保证设计方案永远自洽；
- **防腐蚀**：设计文档中绝不散落大段口语化补丁描述，通过唯一的概念锚标 `<!-- @topic: TopicName -->` 与中枢索引挂接。

---

## 二、极简单一版本号心智 (Single Release Version)

- **文档不设独立版本号**：所有设计文档头部统一只标 `最后更新: YYYY-MM-DD`，绝不浪费算力去计算 `v1.1/v1.2`；
- **全局唯一步调（项目发版号）**：整个工程统一只有一个发布版本号（`v0.1.0` $\rightarrow$ `v0.2.0`），由 Git Tag 和 `CHANGELOG.md` 表达；
- **卡片跟着发版走**：变更卡与任务卡只需声明属于哪个发版批次（如 `"version": "v0.1.0"`），发版时整批归档。

---

## 三、双轨流转与零沉淀纪律 (Dual-Track & Zero-Sediment)

研发工作被严格划分为两条独立轨道：

```
1. 阶段开发轨 (Task Flow)   : 规划方向 -> 架构设计基线 -> M/T 卡拆解 -> 能力交付 -> 阶段封箱
2. 日常维护轨 (Change Flow) : 发现缺陷 -> 变更先行卡 -> 代码/用例 -> 证据代签 -> 回写基线
```

### 零沉淀纪律 (Zero-Sediment Rule)
* `todo/` 只是临时缓冲池，**绝对不是墓地**；
* 事项一旦被建为变更卡（`C 卡`）或立项为任务卡（`T 卡`），**必须立即从 todo 表格中物理删除该行**；
* 杜绝“卡片建了、代码合了，待办表格里还留着陈年僵尸行”的现象。

---

## 四、中枢解耦模型 (Triad Indirection Hub)

```text
       ┌──────────────┐          ┌───────────────────────┐          ┌─────────────────┐
       │ 变更/任务卡   │ <------> │ 索引中枢 (index.json)  │ <------> │ 独立功能微文档   │
       │ Txx / Cxxx   │          │ task/change 唯一路由器 │          │ 0X-功能.md      │
       └──────────────┘          └───────────────────────┘          └─────────────────┘
```

1. **脱钩物理文件**：卡片只声明 `topic` 与 `module`，绝不写死具体的代码文件物理路径，防止重构产生死链；
2. **脱钩标题锚点**：设计文档只声明概念锚标 `<!-- @topic -->`，不依赖易碎的 Markdown 标题 Hash；
3. **版本归档零破坏**：当卡片在发版时被整体移入 `docs/archive/<version>/`，只需更新 `index.json` 中的 `file` 路径，设计文档 0 改动、0 断链。

---

## 五、确定性二值化判据与脱敏证据锚 (Binary Criteria & Secure Evidence)

1. **二值化条件契约**：
   - 验收项严密拆解为 `true_if`（通过依据）与 `false_if`（失败依据）；
   - 执行阶段收集实际输出填入 `evidence`；
   - 裁决只能为 `result: true` 或 `false`，彻底消灭模糊猜测。
2. **脱敏证据锚**：
   - 使用流水号 `run_id`（纯数字或时间戳），杜绝泄漏内网域名或私有仓库拓扑；
   - 严格记录人类在会话中的真实确认原话 `user_quote`，消除 AI 自编自评假代签的信任漏洞。
